# 服务端渲染 vs 终端捕获：发布素材出图路径对比与选型

新品发布素材有两个出图来源可选：**服务端渲染**（后台任务从场景清单重建画面）与
**终端捕获**（在编辑终端上录屏/截屏浏览器预览）。本控制台实现并默认使用**服务端确定性渲染**，
终端（浏览器）预览仅用于交互编辑，不作为发布产物来源。

## 对比

| 维度 | 服务端渲染（本项目实现） | 终端捕获（录屏/截屏） |
| --- | --- | --- |
| **确定性** | 场景清单锁定模型/材质/相机/灯光/纹理版本，输入哈希 = f(清单, 时间线, 渠道配置)；同输入必得同字节帧（本项目两次渲染帧 sha256 逐字节一致，见验收 S8） | 受本机 GPU 驱动、字体、抗锯齿、时基抖动影响，两次捕获几乎不可能逐字节一致，无法用于合规存证 |
| **设备能力** | 不依赖终端 GPU；浏览器只负责查看。低配编辑机也能产出 1080p/竖屏/电视端多渠道成果 | 依赖本机 WebGL/显卡与录屏权限；终端锁屏、掉帧、弹窗都会污染产物 |
| **任务成本** | 任务入队后无人值守批量产出多渠道成果；失败可按依赖诊断重试（本项目渲染任务带 blockers 与 retry） | 每个渠道都需人工值守回放录制，成本随渠道数线性增长，且无法自动重试 |
| **质量门禁** | 缺纹理即阻塞（或显式占位但禁止发布）；字幕安全区冲突写入产物元数据并拦截发布 | 缺纹理可能被本机缓存掩盖；安全区靠肉眼判断，无法机器拦截 |
| **可审计性** | 产物元数据记录全部输入对象 sha256、卖点与证据版本快照，可被 GC/导出器追溯 | 产物无来源信息，无法回答"这帧画面由哪一版模型渲染" |

## 本项目实现的一路：服务端确定性渲染

- **同一场景清单，两处重建**：浏览器 WebGL 预览（`public/gl.js`）与服务端 SVG 渲染器
  （`server/renderer.js`）从同一份场景清单（模型/材质/相机/灯光/纹理的版本与对象哈希）重建画面；
  场景页提供"服务端截图"与浏览器画面并排对比。
- **确定性约束**：帧内容全部数值定点化（坐标 0.1px、颜色整型），文本度量使用内置字宽表而非系统字体，
  输入哈希 = sha256(稳定序列化的清单对象哈希 + 时间线文档 + 渠道配置 + 卖点快照)。
- **门禁**：纹理缺失 → 任务阻塞（可显式 `allowPlaceholder` 生成品红占位内部预览，但占位产物
  无法创建候选发布）；卖点-型号不匹配、证据版本过期 → 渲染即阻塞；字幕安全区冲突 → 记录产物并拦截发布。
- **成本形态**：单任务同步产出某渠道全部帧 + 预览播放器，失败可诊断重试；定时发布到点由调度器执行。

终端捕获仍可用于**内部粗剪沟通**，但进入候选发布（candidate）的产物必须来自服务端渲染任务。
